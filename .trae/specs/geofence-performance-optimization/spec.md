# 轨迹大师地理围栏性能优化 - 产品需求文档 (PRD)

## Overview

- **Summary**: 对轨迹大师应用进行全面的性能优化，包括省电算法、噪点去除算法和围栏边界计算优化，提升应用的能效、定位稳定性和围栏检测准确性。
- **Purpose**: 解决用户反馈的耗电过快、定位漂移导致的误判、以及围栏边界检测不准确等问题，提供更流畅、更准确、更省电的地理围栏追踪体验。
- **Target Users**: 所有使用轨迹大师地理围栏功能的用户，特别是对电池续航、定位精度和围栏检测有较高要求的用户。

## Goals

1. **省电算法优化**
   - 量化评估当前省电算法的能效表现
   - 消除冗余计算，降低资源消耗
   - 制定明确的省电指标和测试方法

2. **噪点去除算法优化**
   - 评估现有噪点去除算法的有效性
   - 建立漂移模式识别机制
   - 开发优化的漂移点识别与排除算法

3. **围栏边界计算优化**
   - 分析围栏边缘定位偏移导致误判的场景
   - 开发智能边界计算逻辑
   - 设计用户友好的围栏绘制指导方案

## Non-Goals (Out of Scope)

- 完全重写现有定位引擎
- 添加新的围栏类型（如圆形/多边形以外的类型）
- 重构整个应用架构
- 添加新的社交或分享功能
- 修改 UI 设计风格（保持现有新复古液态玻璃拟态风格）

## Background & Context

### 现有系统架构

轨迹大师应用已经实现了以下核心功能：

1. **省电算法** (`SmartScheduler.kt`)
   - 已实现：静止判定（距离 + 加速度）、阶梯降频、边界 Buffer 区检测、三电源模式（performance/balanced/powersave）
   - 问题：降频阶梯可能不够合理，边界 Buffer 计算可能存在冗余

2. **噪点去除** (`Engine.kt`, `SmartScheduler.kt`)
   - 已实现：简单的 accuracy > 50m 过滤
   - 问题：缺少更复杂的漂移模式识别，对渐变漂移处理不足

3. **围栏边界计算** (`GeoMath.kt`)
   - 已实现：标准射线法 point-in-polygon、BBox 快速过滤
   - 问题：没有边界 buffer 处理，定位偏移时容易误判

### 技术约束

- 保持与现有代码库的兼容性
- 使用 Kotlin 语言和 Jetpack Compose 框架
- 集成高德地图 SDK
- 最低支持 Android 8.0（API 26）

## Functional Requirements

### FR-1: 省电算法评估与优化
- **FR-1.1**: 实现省电效果量化统计功能，记录不同模式下的定位频率和电池消耗
- **FR-1.2**: 优化静止判定算法，减少误判
- **FR-1.3**: 调整降频阶梯参数，提供更平滑的省电过渡
- **FR-1.4**: 优化边界 Buffer 检测算法，减少不必要的计算
- **FR-1.5**: 添加省电效果可视化展示

### FR-2: 噪点去除算法优化
- **FR-2.1**: 实现定位漂移模式识别（突发漂移、渐变漂移）
- **FR-2.2**: 开发卡尔曼滤波器或类似算法进行位置平滑
- **FR-2.3**: 实现基于历史轨迹的异常点检测
- **FR-2.4**: 添加可配置的噪点过滤参数
- **FR-2.5**: 记录和展示过滤掉的噪点数据用于调试

### FR-3: 围栏边界计算优化
- **FR-3.1**: 实现围栏边界 Buffer 区（边界容错区）
- **FR-3.2**: 开发基于定位精度的动态边界调整
- **FR-3.3**: 实现围栏绘制时的智能提示系统
- **FR-3.4**: 添加边界误判检测和自动补偿机制
- **FR-3.5**: 提供围栏边界可视化调试工具

## Non-Functional Requirements

### NFR-1: 性能指标
- **NFR-1.1**: 省电模式下相比性能模式，电池消耗降低 60% 以上
- **NFR-1.2**: 围栏检测延迟不超过 100ms
- **NFR-1.3**: 位置平滑算法处理延迟不超过 50ms
- **NFR-1.4**: 内存使用增加不超过 10%

### NFR-2: 准确性指标
- **NFR-2.1**: 噪点去除率达到 90% 以上
- **NFR-2.2**: 边界误判率降低 80% 以上
- **NFR-2.3**: 静止判定准确率达到 95% 以上

### NFR-3: 用户体验
- **NFR-3.1**: 所有优化对用户透明，无需额外配置
- **NFR-3.2**: 提供可选的高级设置面板
- **NFR-3.3**: 优化后界面响应速度不低于现有水平

## Constraints

### 技术约束
- **语言**: Kotlin 1.9+
- **框架**: Jetpack Compose 1.5+
- **最低 SDK**: Android 8.0 (API 26)
- **地图 SDK**: 高德地图最新稳定版
- **构建工具**: Gradle 8.0+

### 业务约束
- **时间表**: 2 周内完成开发和测试
- **兼容性**: 必须与现有数据格式完全兼容
- **回滚**: 必须提供回滚到旧算法的选项

### 依赖约束
- 依赖现有 `GeoMath.kt`, `Engine.kt`, `SmartScheduler.kt` 模块
- 不引入新的第三方库（除非经过评估）

## Assumptions

1. 用户设备支持加速度传感器（用于静止判定）
2. 高德地图 SDK 提供的定位精度信息可靠
3. 现有围栏数据格式不需要修改
4. 用户愿意在设置中启用高级优化功能（如需要）
5. 测试设备覆盖主流 Android 机型和 Android 版本

## Acceptance Criteria

### AC-1: 省电算法优化验证
- **Given**: 用户在平衡模式或省电模式下使用应用
- **When**: 连续使用 2 小时
- **Then**: 电池消耗相比优化前降低 40% 以上（通过电池统计工具测量）
- **Verification**: `programmatic`
- **Notes**: 需要在相同设备和使用场景下进行对比测试

### AC-2: 静止判定准确率提升
- **Given**: 用户手机静止放置 10 分钟
- **When**: 定位系统运行
- **Then**: 静止判定准确率达到 95% 以上，误触发移动的次数不超过 2 次
- **Verification**: `programmatic`

### AC-3: 噪点去除效果
- **Given**: 存在定位漂移的测试数据集
- **When**: 应用噪点去除算法
- **Then**: 90% 以上的明显漂移点被正确识别和过滤
- **Verification**: `programmatic`

### AC-4: 位置平滑效果
- **Given**: 连续的定位数据流
- **When**: 应用位置平滑算法
- **Then**: 位置轨迹平滑度提升 50% 以上（通过轨迹波动方差测量）
- **Verification**: `programmatic`

### AC-5: 围栏边界 Buffer 效果
- **Given**: 用户在围栏边界附近（距离边界 10-20 米）
- **When**: 定位有轻微偏移（±15 米）
- **Then**: 围栏状态保持稳定，不会频繁切换进入/离开
- **Verification**: `human-judgment`
- **Notes**: 需要实际测试不同定位精度场景

### AC-6: 围栏绘制指导
- **Given**: 用户正在创建新围栏
- **When**: 用户绘制围栏边界
- **Then**: 系统提供清晰的绘制指导，建议围栏大小至少为预期范围的 1.2 倍
- **Verification**: `human-judgment`

### AC-7: 性能无退化
- **Given**: 优化后的应用
- **When**: 执行常规操作（创建围栏、查看统计等）
- **Then**: 界面响应时间不超过 300ms，无明显卡顿
- **Verification**: `human-judgment`

### AC-8: 数据兼容性
- **Given**: 优化前创建的围栏数据
- **When**: 使用优化后的应用加载
- **Then**: 所有数据正常显示，功能正常使用
- **Verification**: `programmatic`

### AC-9: 省电效果可视化
- **Given**: 用户打开设置页面
- **When**: 查看省电统计
- **Then**: 显示清晰的省电效果数据（定位频率、预计省电百分比）
- **Verification**: `human-judgment`

### AC-10: 可配置性
- **Given**: 用户打开高级设置
- **When**: 调整优化参数
- **Then**: 参数立即生效，且提供重置为默认值的选项
- **Verification**: `human-judgment`
