## Codebase Patterns
- GeoFence data model exists in two places: `data/FenceData.kt` (UI layer) and `core/GeofenceModels.kt` (Engine layer). The UI layer `GeoFence` uses `categoryId` while Engine uses `category` - both need to be kept consistent
- Build system uses Gradle 9.0 with `JAVA_HOME=/d/javajdk` on this machine
- The project has both unit tests and instrumentation tests - unit tests have pre-existing Int vs Long type mismatch issues in `StayDurationManagerTest.kt`
- GeofenceDatabaseHelper already has comprehensive table definitions including fences, categories, events, stays, daily_stays tables
- PersistentStateManager handles SharedPreferences-based state persistence for fence enter/exit times
- Engine.kt in core/ handles the nested timing logic with findAllMatchedFences() and state machine
